# v0.1 Release Runbook

## 1 · 先看真实门禁

```text
python3 scripts/check_release_readiness.py
```

无论 ready 或 blocked，命令都会更新 `releases/v0.1-rc/readiness.json` 和 `readiness.md`。blocked 会返回非零；按 must-blocker、must-missing、review-required、known-gap 顺序处理。`--allow-blocked` 只用于诊断，不能授权发布。

## 2 · 审计能力与写作进度差异

```text
python3 scripts/audit_roadmap_evidence.py
```

报告区分真正 done、已有文件待人工验收、路径分歧和缺失，且不会修改 `progress/tasks.json`。

## 3 · ready 后生成 Notes 与候选

```text
python3 scripts/render_release_notes.py --require-ready
python3 scripts/prepare_release.py v0.1 \
  --readiness releases/v0.1-rc/readiness.json \
  --release-notes releases/v0.1-rc/release-notes.md
```

readiness 与当前 source 不一致时拒绝混合。HTML 必交；PDF 缺失时明确 skipped。

## 4 · GitHub 发布与下一周期

`release.yml` 总会保留 readiness artifact，但 blocked 时不 build/publish。真实 `release.published` 触发 `post-release.yml`；脚本会在 tag checkout 上重新计算 readiness 并核对 source SHA，然后生成回执、激活 v0.2、记录事件、重建驾驶舱，并提交自动化 PR。重复处理同一发布保持幂等；权限不足时保留 recoverable artifact。

## 5 · 当前状态

当前是否存在 remote 不影响本地门禁。真实进度以 [`progress/generated/current.json`](../progress/generated/current.json) 为准；只要 v0.1 Must 任务、审校或发布证据未齐，readiness 就应保持 `blocked`。这是门禁正确阻止未完成内容冒充 v0.1。
